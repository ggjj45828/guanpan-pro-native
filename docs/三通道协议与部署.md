## 数据隔离

| 入口 | 存储 | 规则 |
| --- | --- | --- |
| /api/data | 原 sync.sqlite3 的 legacy | 保持旧网页兼容；新增可选 expectedRevision 冲突校验 |
| /api/native/data | 原 sync.sqlite3 的 native | 保留旧原生协议；CAS 和事务内空覆盖保护 |
| /api/v2/channels/assets | 新 channels-v2.sqlite3 | 真实资产通道，写入须 intent=manual |
| /api/v2/channels/market | 新 channels-v2.sqlite3 | 行情通道，不允许真实账本顶层字段 |
| /api/v2/channels/quant | 新 channels-v2.sqlite3 | 实验账本/策略/决策通道，不允许真实账本顶层字段 |

新通道不读取或转换原数据库，也不会自动拆分旧 native 文档。**现有采集器还没有把分时/IOPV/K线写进 v2 market**，因此新行情通道为空是正常的，不能显示成“行情已同步”。旧市场归档接口仍保留。

市场/量化允许自动客户端，资产强制手动意图；服务器不能仅凭 intent 字符串证明用户点击行为，仍需客户端流程保证。
通道顶层字段隔离已测试，但深层证券/决策等业务对象目前仍是 JSON 载荷，不是完整领域模型验证。

## API

GET `/api/v2/channels` 返回每通道模式、版本、摘要；不返回账本内容。
GET `/api/v2/channels/{channel}` 返回 `{schemaVersion:2,channel,revision,digest,data}`。
POST 同一地址执行完整通道文档的 CAS 替换（不是单条记录合并）：

```json
{
  "schemaVersion": 2,
  "expectedRevision": 0,
  "requestID": "unique-client-request-id",
  "intent": "manual",
  "data": {"holdings": [], "cash": 1000000, "asOf": 1792375200000}
}
```

示例 cash=1000000 表示 100 元。新域所有金额/价格均使用 **1/10000 元整数**，时间使用 UTC 毫秒。旧协议依旧使用原来的金额格式，不能直接混发。

- assets 字段：holdings、cash、ledger、costs、cashFlows、asOf。
- market 字段：quotes、iopv、intraday、daily、books、quality、asOf。
- quant 字段：lab、strategies、orders、fills、decisions、reviews、backtests、asOf。
- 每次写入必须带非负整数 expectedRevision。并发旧版本返回 409。
- 同通道相同 requestID 和同请求原文返回第一次结果；换请求复用 ID 返回 409。网络重试必须复用原 requestID。
- 内容摘要不变时不产生新版本；requestID 仍记录用于防重。
- 有内容的通道不能被空内容覆盖，除非显式 `allowEmptyOverwrite:true`；保护位于写事务内。
- 通道单文档最多 16 MiB；全量历史目前永久保留，后续需要容量管理。
- GET `/{channel}/history` 返回最近最多 100 条历史元信息；历史记录本身不裁剪。
- POST `/{channel}/restore` 带 schemaVersion、expectedRevision、requestID、restoreRevision；资产仍须 manual。恢复生成新版本，不修改旧版本。
- `ChannelStore.backup(new_path)` 使用 SQLite backup API 生成新文件，不覆盖已存在备份。已测试；尚无自动备份任务或管理 UI。

鉴权沿用旧服务器 SYNC_TOKEN；配置为空时沿用局域网免口令行为。新版 Compose 用 `${SYNC_TOKEN:-}` 从运行环境读取；原来若配置过口令，需要在部署环境保留相同值。v2 不接受 body.tok，使用 Authorization Bearer（或旧鉴权允许的查询参数）；客户端使用请求头。
`/api/native/ping` 已改为鉴权后只返回元数据，data=null；不再经健康探针暴露完整真实账本。

## iOS 接入范围

新实验室页面中有独立状态和进度。页面打开期间自动检查，每 60 秒重试：

- assets：显示默认手动、未迁移；本页面不会读写真实账本。
- market：读取新通道并保留在页面协调器内存，尚未合并到现有图表。
- quant：同步独立 lab；无共同基线或双端变化时暂停；不同实验 ID 不互相替换；保留远端其他量化字段。接收时校验并写入独立实验文件。

自动循环不是全 App 后台任务，页面关闭即停止。Swift 接入未编译，未进行真机或实际 NAS 联调，不能视为三通道端到端完成。
真实账本旧自动同步开关使用新 opt-in 键，默认 false；旧开关值保留但不自动继承。用户仍可手动使用旧安全同步和备份入口，旧协议尚未拆分。

## 部署方式

先在副本环境运行 `python tests/run-validation.py`，再在 macOS 构建 iOS。当前已验证本机 Python 服务与临时 SQLite，不等于 Docker 或 NAS 实机通过。

部署时同时提供 server.py 与新增 channel_store.py（Compose 已增加只读挂载，Dockerfile 已增加 COPY）。沿用原 data 挂载；此源码包不提供 data/ 内容，不要用上传包数据库覆盖运行中的真实数据库。
启动后仅首次使用新 API 时创建 channels-v2.sqlite3。不会自动迁移旧账本，也不会自动启动模拟下单任务。

回滚代码之前先备份两套数据库。旧代码不认识 channels-v2.sqlite3，会忽略它；保留该文件可供后续恢复。原服务器启动本身可能维护旧库表结构，测试未运行用户实例，不能承诺所有旧部署无条件可回滚。
