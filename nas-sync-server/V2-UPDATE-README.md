# 观盘 Pro NAS v2 通道更新包

此包在 NAS 上增加独立的真实资产、行情数据和 AI 量化 v2 通道，同时保留原有网页账本 `/api/data`、iOS 原生账本 `/api/native/data`、行情代理及网页。v2 使用单独的 SQLite 文件；更新代码不会把模拟交易写入真实账本。

## 更新前保护数据

先在 NAS 的旧服务管理界面记下当前目录、端口、环境变量及口令配置。停掉旧容器后，复制整个旧 `data/` 目录到 NAS 另一个位置作为备份；如果只能在线复制 SQLite 文件，请使用 SQLite 的备份功能，不能只复制正在写入的主数据库文件。保留旧容器镜像/源码和 compose 文件，直到新版本验证完毕。不要把任何 `data/`、数据库、`-wal`、`-shm` 或口令文件放进更新包。

## 先并行试运行

1. 把解压后的 `guanpan-nas-v2-update` 文件夹放到 NAS 的新目录。保留旧服务运行。
2. 复制 `.env.example` 为 `.env`。将 `SYNC_TOKEN` 设置为旧服务使用的同一口令；如果旧服务未设口令则留空。不要把 `.env` 分享或提交到代码仓库。
3. 在此目录执行 `docker compose up -d`。包默认使用 NAS 端口 **8789**，因此不会占用你旧版的 **8788**。持久数据只写入此目录新建的 `data/`。
4. 查看状态：`docker compose ps` 和 `docker compose logs --tail=100`。在浏览器打开 `http://NAS地址:8789/api/ping`，应返回 `ok:true`、`proxy:true`。
5. 检查旧客户端接口仍在：访问 `http://NAS地址:8789/api/native/ping`。无口令配置时应返回 `ok:true`；有口令时加请求头 `Authorization: Bearer 你的口令`。网页及 iOS 旧账本路径仍为 `/api/data` 与 `/api/native/data`。
6. v2 接口需要同一同步口令（如果配置了）：`GET /api/v2/channels/status`、`GET /api/v2/market/records?kind=quote` 和 `GET /api/v2/market/universe?limit=20`。这些只读请求可以确认三通道服务与离线空数据响应；尚未接入行情服务时，不能据此认为已经有全市场覆盖或五档盘口。
7. 使用 v2 iOS 候选版时先只连接试运行端口 `8789`，确认页面、旧账本读取、三通道独立状态与同步错误提示。先不要把真实账本下载到空白试运行库后再上传；真实资产同步必须在客户端预览并由用户确认。

## 将服务切换到 8788

完成并行验证、确认旧 `data/` 备份可读后，再安排停机窗口：停止旧服务，把 NAS 端口 `8789:8787` 改成 `8788:8787`（或设置 `V2_HOST_PORT=8788`），启动此目录服务。确认 `/api/ping`、`/api/native/ping` 和 App 同步后再移除旧容器。新服务会继续读取自己目录的 `data/`；它不会自动导入旧数据目录，也不会覆盖旧数据库。旧账本继续由原生通道 CAS/冲突保护处理。

旧服务数据库不会因为升级而迁入 v2。新市场历史与通道数据库保存在 `data/market-v2.sqlite3`、`data/channels-v2.sqlite3`；v2 策略账户属于量化通道。历史数据只会在 NAS 有合法数据源、完成入库后逐步累积。

## 数据源配置与限制

未提供数据服务时服务仍能独立运行，并接受离线研究 JSON 导入。`V2_FEED_URL` 可填自建的标准化行情服务地址，`V2_FEED_TOKEN` 只在 NAS 本机 `.env` 中设置。行情服务必须返回文档约定的时间、代码、价格与来源字段。五档数量单位需由数据供应商确认后才能设置 `V2_BOOK_VOLUME_MULTIPLIER`；未确认时不要伪造盘口成交量。离线导入命令和 JSON 约束见主仓库 `nas-sync-server/部署说明.md`。

## 回滚

并行试运行不满意时，执行 `docker compose down` 停止本更新包，然后继续使用原服务和原端口。切换到 8788 后需要回滚时，先停止新服务，再恢复旧 compose/代码和之前备份的旧 `data/`。**不要把 v2 的 SQLite 文件复制覆盖旧数据库，也不要把旧版程序指向含有 v2 写入的新数据库。** 这样旧版回滚不会误读或修改 v2 账本。

本更新包不指定固定的 `container_name`，由 Compose 根据项目目录生成独立容器名，避免与旧版 `guanpan-nas-sync` 发生名称冲突。请从新包目录启动；不要为了消除冲突而删除旧容器。新服务使用 8789 端口和本包目录下独立的 `data/`。

本包不替你连接或更新 NAS。本地验证通过也不等于 NAS 已部署；升级后仍需在 NAS 端核对容器日志、旧接口和 App 连接。
