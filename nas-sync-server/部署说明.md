# 观盘 Pro · 一体化服务器（网页托管 + 行情代理 + 双分区同步）

一个容器同时干三件事，网页版和 App 版共用，数据互不干扰。

```
网页版  /api/data         → 分区 legacy
App 版  /api/native/data  → 分区 native
行情    /api/quote|kline|minute|holdjson|fundinfo
```

---

## 一、和之前那版服务器的关键区别

| | 旧同步服务器 | 现在这版 |
|---|---|---|
| 行情代理 | 有 | **有（已补回）** |
| 分区 | 单分区 | **legacy / native 双分区** |
| 存储 | JSON + 一个 .bak | **SQLite，保留最近 10 个历史版本** |
| K 线 | 单源 | **三源自动降级** |
| 空数据覆盖 | 网页通道不拦 | **两条通道都拦（409）** |
| 口令 | 必须 | **可选（留空即免口令）** |

### 行情代理为什么必须有

```
有代理  手机 → NAS → 腾讯行情     手机不用能上外网
没代理  手机 → 直连腾讯行情域名   手机必须能上外网
```

前端靠 `GET /api/ping` 返回 `ok:true` 判定"服务器是代理"，之后才把行情改写成 `/api/quote`。
所以 ping 必须回 `ok:true` + `proxy:true`，否则行情全部走直连。

## 三、部署

```bash
cd guanpan-sync
docker compose up -d
```

默认端口 **8788**（外）→ 8787（内），避免跟旧服务器冲突。旧的停了可改回 `8787:8787`。

没有 Docker 也能跑：

```bash
SYNC_TOKEN="" DATA_DIR=./data PORT=8788 python3 server.py
```

## 四、口令（可选）

```yaml
SYNC_TOKEN: ""        # 留空 = 免口令
SYNC_TOKEN: "你的口令"  # 设了才需要
```

设了之后：

| 接口 | 要不要口令 |
|---|---|
| `/api/data`、`/api/native/data` | **要** |
| `/api/ping`、行情代理 | 不要（行情是公开数据，且前端要靠 ping 探活） |

三种传法都认：
```
?tok=xxx
Authorization: Bearer xxx
POST body 里的 tok
```

> ⚠️ **免口令模式仅限局域网**。不要把 8788 端口映射到公网，
> 否则任何人都能读写你的账本。

## 五、App 里填什么

| 项 | 值 |
|---|---|
| 地址 | `http://NAS的IP:8788` |
| 口令 | 与你 compose 里设的一致；没设就留空 |

**地址不要带 `/api/...`**，App 自己会拼 `/api/native/data`。

### 本轮修掉的一个 bug

`/api/kline` 必然 502。原因是 `do_proxy` 里 kline 分支没给 `url` 赋值，
下一行 `url.endswith(".js")` 直接 `NameError`，被 except 兜住变成"代理拉取失败"。

表现是：**价格正常、分时正常，唯独技术复盘全空**。已修。

### K 线代理回调修复

网页版通过脚本回调变量读取 K 线。NAS 代理改写请求时此前没有把 `_var` 回调名继续传给腾讯，
即便上游返回了内容，浏览器也可能一直等不到 K 线对象。当前版本会保留回调名、校验回调格式，
并将代理响应按 JavaScript 返回。行情报价与 K 线使用不同的腾讯域名，因此报价正常不代表 K 线上游也可达。

更新后替换 `server.py` 和 `web/index.html` 并重启容器。若仍提示 K 线失败，再在 NAS 容器内分别检查
`proxy.finance.qq.com`、`ifzq.gtimg.cn`、`web.ifzq.gtimg.cn` 的外网连通性；`/api/ping` 成功只说明本地 NAS 服务可用。

## 九、排障

| 现象 | 原因 / 处理 |
|---|---|
| 行情全部失败 | ping 是否返回 `proxy:true`；不是则代理未生效 |
| 价格有、技术复盘空 | K 线源不通。ping 里的 `klineHost` 是当前用的源，三源会依次降级 |
| App 报「版本已变化」 | App 先下载一次刷新 revision 再上传 |
| 401 | 口令不对；或 compose 里 `SYNC_TOKEN` 改过没重启 |
| 浏览器打不开 | `web/index.html` 没放，或挂载路径不对 |
| 上游超时 | 家里网慢，把 `UPSTREAM_TIMEOUT` 调到 20 |

### 为什么同步地址里的端口看起来会变

当前 Compose 映射是主机端口 `8788` → 容器端口 `8787`；服务进程始终监听容器内的 `8787`，
浏览器在局域网应固定使用 `http://NAS_IP:8788`。源码没有随机分配主机端口的逻辑。
如果从极空间的应用入口打开，地址栏可能显示 127.0.0.1:1000x。这是极空间为网页访问分配的临时代理端口，
不是 Docker 端口，也不会替换 8788:8787 映射。直接在局域网使用 http://NAS_IP:8788 仍是固定入口。
新版网页遇到 127.0.0.1 临时代理时，会用当前页面的同源请求连接 NAS，不保存临时端口；端口变化后也不再误报“未填写服务器地址”。
浏览器会按“协议 + 域名 + 端口”隔离本地设置，所以临时代理下只把本次页面连接视为已连接。其他设备若需配置固定同步地址，
请填写 NAS 固定内网地址或固定穿透域名，不要填写 127.0.0.1:1000x。
